# Mini-Inference Documentation

## Authority order

1. `../PROJECT_CONSTITUTION.md`
2. Approved product requirements in `product/`
3. Effective architecture decisions in `adr/`
4. Technical specifications in `technical/`
5. Implementation plans in `plans/`
6. Test specifications and revision-bound reports in `quality/`
7. Operations runbooks in `operations/`

## Status vocabulary

- Draft: under preparation; not an implementation authority.
- Approved: product scope accepted by the user.
- Effective: architecture decision accepted by the user.
- Superseded: retained for history but no longer governs new work.
- Evidence: revision- or runtime-bound observation, not policy.

Documents must identify status, owner, inputs, and acceptance or verification evidence. Later artifacts cannot silently change earlier approved facts.

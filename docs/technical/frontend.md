# Mini-Inference 前端技术规格

- **状态：** Implementation-ready
- **所有者：** 前端开发工程师
- **适用范围：** MVP 简体中文运维控制台；iOS 可作为公开 API 客户端适配，但不在本控制台实现范围内，也不得承担服务端或本地推理
- **权威输入：** `PROJECT_CONSTITUTION.md`、`docs/product/01-prd.md`、`docs/adr/0001-system-architecture.md`、`docs/adr/0002-project-built-compatible-dmr.md`、`docs/adr/0004-restore-mac-deployment-target.md`、`docs/architecture/00-dmr-research.md`、`docs/architecture/01-controller-feasibility.md`
- **契约生产者：** `api`，其管理端契约由 `docs/technical/backend.md` 唯一定义

## 1. 设计解读、范围与非目标

### 1.1 Design Read

将本产品理解为：**面向唯一维护者、运行在受信任私有网络中的技术运维仪表盘；视觉语言应克制、信息密集、可信且可快速扫描，采用 IBM Carbon Design System，不采用渐变光晕、玻璃拟态、聊天框、AI 紫色或装饰性“智能仪表盘”元素。**

设计参数为：视觉变化度 3/10，动效强度 2/10，信息密度 8/10。信息架构优先支持判断“现在是否安全可用、队列正在发生什么、动作是否真正完成、数据与备份是否正常”，而非营销展示。

### 1.2 本规格负责

- 简体中文信息架构、路由、页面层级和导航；
- Carbon 组件选择、视觉 token、状态表现、响应式与浏览器支持；
- 模型启动、停止及等待请求取消的交互和确认；
- 服务、模型、唯一活跃请求、FIFO 队列、资源、指标、趋势、告警、结构化日志、保留和备份状态的展示；
- 加载、空、错误、陈旧、不可用及动作过渡状态；
- 键盘、焦点、语义、实时播报、图表和表格可访问性；
- 消费 `api` 发布的管理端 HTTP/SSE 契约及恢复行为；
- 浏览器验收场景与 PRD AC 追踪。

### 1.3 非目标

- 不提供聊天或提示词输入界面，不显示提示词、回答、推理内容或工具参数正文；
- 不提供登录、用户、角色或前端权限模型。隐藏控件、禁用按钮和路由均不是授权；
- 不直接访问 `controller`、DMR、PostgreSQL、Docker Engine 或宿主机接口；
- 不执行任意 Docker 命令，不允许重排队列，不提供外部通知；
- 不在客户端推导模型就绪、动作成功、请求终态、可重试性、指标或备份事实；
- 不实现精确实时 GPU 利用率、多模型、未批准部署环境界面分支、HA 或第二运行时；
- 不把浏览器缓存、SSE 事件或客户端遥测当作业务审计证据。

## 2. 技术与设计系统

### 2.1 唯一设计系统

选择 **IBM Carbon Design System for React**。实现只引入同一体系内的以下依赖，并在版本清单中精确固定版本：

- `@carbon/react`；
- `@carbon/styles`；
- `@carbon/icons-react`；
- `@carbon/charts-react`，仅用于本规格列出的请求、token 与性能时间序列，禁止再引入第二套图表库。

不混用 Material、Fluent、Ant Design、shadcn/ui 或其他组件系统。Carbon 适合高密度运维和分析场景，具有成熟的 DataTable、InlineNotification、Modal、Skeleton、Tag、Tabs、Pagination、Tooltip 和可访问性模式。图表必须同时提供表格数据视图，因此图表库不是事实的唯一呈现。

图标只使用 `@carbon/icons-react`；同一语义在所有页面使用同一图标。非视觉基础设施仅选 `react-router-dom` 处理上述五个静态路由、`@tanstack/react-query` 处理服务端缓存与条件重取；不用第二状态库、动画库或日期库。SSE 使用浏览器流能力实现可带 `Last-Event-ID` 的客户端，不增加 SSE 包。所有直接和传递依赖在版本清单中固定；本技术规格不执行安装。

### 2.2 前端技术边界

- React + TypeScript 静态前端，浏览器只访问同源 `api` 管理端路径；
- 服务端数据由一套查询缓存管理，不以 `useEffect + useState` 复制服务器事实；
- 本地状态仅含导航展开、当前游标页、日志级别、图表时间窗、对话框开关和未提交确认；
- 所有服务端时间以契约中的 UTC RFC3339 解析，显示为浏览器本地时间，并在 Tooltip/详情中同时展示带时区的绝对时间；
- 请求标识按原值显示为截断的等宽文本，复制操作复制完整标识；任何标识不得包含正文。

## 3. 权威边界与数据流

`api` 是服务、模型、队列、请求、指标、告警、日志、保留、备份、操作结果和重试资格的唯一权威。前端只做以下转换：

1. 将稳定枚举映射为简体中文标签、图标、形状与颜色；
2. 将数值按契约单位格式化，不换算或补造缺失样本；
3. 将权威时间转为本地显示格式；
4. 保留最后一次成功快照以提供陈旧提示，但不把旧数据标为当前事实；
5. 动作完成后等待权威操作结果和/或新快照，不因 HTTP 提交成功、按钮动画或 SSE 到达而自行宣告业务成功。

禁止从以下信号推导业务状态：按钮是否禁用、当前路由、SSE 是否连接、浏览器计时器、某个请求是否从当前分页消失、HTTP 连接是否关闭、客户端乐观更新。若 `api` 对模型状态或动作结果返回未知枚举，使用“无法识别的状态”，保留原始安全代码用于诊断，并禁用会扩大影响的动作；不得映射为“就绪”或“成功”。

## 4. 信息架构与导航

采用 Carbon `Header` + 可折叠 `SideNav` + 主内容区。桌面端固定左侧导航，窄屏使用菜单按钮展开覆盖式导航。提供“跳到主要内容”链接。路由均可直接刷新和用浏览器前进/后退恢复；指标时间窗、日志级别和不透明分页游标写入 URL 查询参数，不包含敏感信息。

| 路由 | 导航名称 | 主任务 | 核心内容 |
|---|---|---|---|
| `/` | 运行总览 | 立即判断系统是否可用并执行模型动作 | 服务/模型状态、启动/停止、唯一活跃请求、FIFO 队列前几项与总深度、资源摘要、当前告警、最近备份摘要 |
| `/requests` | 请求与队列 | 观察单活跃/FIFO，取消等待项，检查终态 | 活跃请求、完整等待队列、最近请求元数据表与游标分页 |
| `/metrics` | 指标与趋势 | 查看有明确来源的资源状态及请求、token 和性能趋势 | API 容器 CPU、DMR 模型进程统一内存、项目/模型/运行时存储、DMR 推理引擎 Metal；请求量；输入/输出/推理 token；吞吐、首 token 时间、总时长；可复现基线说明 |
| `/alerts` | 告警与日志 | 定位内容安全的运行问题 | 告警列表、结构化日志表、日志级别筛选、关联安全代码与时间 |
| `/data` | 数据与备份 | 检查保留、备份和恢复证据 | 30 天保留状态、最近清理、最近每日备份/7 天保留计数、最近恢复证明 |

页面标题使用一个 `h1`；各区域按 `h2`；卡片内部不得用视觉字号替代标题语义。总览只展示摘要并链接至对应完整页面，避免复制两套行为实现。全局 Header 显示产品名“Mini-Inference 运维控制台”、服务状态简标和“无需登录，仅限私有网络”文本，不显示虚假的用户头像或通知入口。

### 4.1 运行总览

自上而下排列：

1. **状态带：** 服务状态、模型状态、快照采样时间、更新连接状态。连接状态不得覆盖模型状态；“更新已断开”不等于“模型不可用”。
2. **模型控制：** 唯一模型名称与不可变模型标识、生命周期标签、最近状态变化时间、安全失败摘要、启动或停止按钮。
3. **当前执行：** 活跃请求单行详情；右侧显示等待深度 `n / 20`。无活跃请求时保留区域结构。
4. **FIFO 队列：** 前 5 项，固定按权威 `position` 升序；提供“查看全部”。不提供排序控件、拖拽或批量取消。
5. **资源摘要：** 四项固定标签为“API 容器 CPU”“DMR 模型进程统一内存”“项目/模型/运行时存储”“DMR 推理引擎 Metal”。每项同时显示值、采样时间与来源；Metal 只显示“已启用 / 未启用 / 无法获取”。不得缩写成会被理解为整台 Mac 的“CPU / 内存 / 磁盘”。
6. **运行关注项：** 当前告警摘要和最近备份状态。无告警是明确健康空状态；无法读取不是无告警。

### 4.2 请求与队列

- 活跃请求始终独立于等待表，明确注明“最多 1 个”；
- 等待表列为：顺位、请求标识、进入队列时间、已等待、超时截止时间、状态、操作。顺位来自后端，不按客户端时间重算；
- “取消”只在等待项 `can_cancel=true` 时显示；没有该值时不显示，并不代表鉴权；
- 最近请求元数据表逐字段展示生产者允许的非内容字段、token 计数、时延和终态；绝不提供正文搜索；
- 请求状态标签覆盖 `waiting|active|succeeded|failed|cancelled|queue_timeout|interrupted|rejected`，未知值显示“无法识别”且不丢行；管理 API 未发布状态或时间筛选，前端不得添加会让单页数据看似全局结果的筛选；
- 表格按生产者固定的 `created_at DESC,id DESC` 顺序使用不透明 `next_cursor` 分页，不提供客户端排序。刷新当前游标失败或因保留清理而失效时回到第一页并播报。

### 4.3 指标与趋势

默认使用 `1h/1m`；时间窗和粒度只允许 `1h/1m`、`24h/1h`、`7d/1h`、`30d/1d` 四个生产者组合，不请求任意聚合。

- 资源区：只展示 Snapshot 当前四项资源卡片及 `sampled_at` 和各自 source；生产者未发布资源历史序列，禁止绘制资源趋势、Metal 利用率或物理 Mac/Docker VM 总量；
- 请求区：请求总量及终态分组；
- Token 区：输入、输出、推理 token 三条可区分序列；
- 性能区：吞吐、首 token 时间、请求总时长。单位直接来自契约；不同单位不得放在同一 Y 轴；
- 每个图表上方展示时间窗和采样/桶粒度，下方提供“查看数据表”切换；
- 缺桶显示断线或“无样本”，不得补零；真实零值必须显示为 0；
- 基线只展示记录条件与数值，不根据数值高低显示通过/失败。

资源卡片的可见来源文案固定如下，不能只在 Tooltip 中提供：

| wire source | 可见来源文案 | 数值解释 |
|---|---|---|
| `api_container` | “来源：API 容器” | `cpu_percent` 仅表示 API 容器 CPU 百分比，不是 DMR、Docker VM 或物理主机总 CPU |
| `dmr_process`（统一内存） | “来源：DMR 模型进程” | used 为 DMR 模型进程已用统一内存；total 仅为生产者可证明的进程/运行时限额，不是物理 Mac 总内存 |
| `project_storage` | “来源：项目/模型/运行时存储” | used/total 只覆盖该存储范围及可证明容量/限额，不是整块物理磁盘 |
| `dmr_process`（Metal） | “来源：DMR 推理引擎” | 只表达引擎是否启用 Metal，不表达 GPU 利用率 |
| `unavailable` | “来源：无法获取” | 数值保持 null，Metal 保持 unknown；可见值统一为“无法获取”，不得显示 0 |

`resources.status=partial` 时每张卡独立依据自己的 `*_source` 展示，不能用一项可用推断其他项可用。`reason_code` 在资源区顶部作为安全诊断代码显示。

### 4.4 告警与日志

告警按生产者顺序显示严重度、稳定代码、安全摘要、首次/最近发生时间和状态。颜色以外同时使用图标与文本。结构化日志仅显示后端已净化字段；前端不得尝试渲染任意 JSON 对象、HTML、Markdown 或堆栈中的非契约字段。安全摘要按纯文本渲染。

“当前无告警”只在成功读取且集合为空时出现。日志为空写“当前日志级别下没有日志”。日志仅支持 `info|warning|error` 级别筛选；告警不提供客户端筛选。日志读取失败、告警读取失败各自局部呈现，不让一个区域遮蔽另一个区域。

### 4.5 数据与备份

- 保留策略固定显示“请求元数据保留 30 天”，并展示 `cutoff_at`、`last_run_at`、`outcome` 和 `deleted_rows`；
- 备份策略固定显示“每日逻辑备份，仅保留最近 7 天”，展示最近执行时间、结果、仅含 basename 的 `artifact_name`、`retained_count` 和 `next_expected_at`；契约不提供备份集合、大小或下载入口，前端不得补造；
- 恢复证明显示 `last_run_at`、`outcome`、`restored_request_count` 和三类 `restored_token_totals`，不提供从浏览器发起恢复的动作；
- `outcome=unknown` 或 nullable 时间表示“尚无可确认的证据”，不得显示为成功或失败；
- 此页不展示仓库绝对路径、数据库凭据、命令、下载入口或正文内容。

## 5. 生命周期与操作交互

### 5.1 模型状态呈现

| 权威含义 | 中文标签 | 视觉与动作规则 | 辅助文案 |
|---|---|---|---|
| 已卸载 | 已卸载 | 中性方形标签；仅允许后端声明可用的“启动模型” | “模型未加载，新的推理请求不会进入队列。” |
| 启动中 | 启动中 | 蓝色进度图标，动效可关闭；不显示就绪；所有生命周期按钮禁用 | “正在加载并预热模型，请等待权威结果。” |
| 就绪 | 就绪 | 绿色勾选加标签；显示“停止模型” | “模型已完成加载和预热，可以接收推理请求。” |
| 停止中 | 停止中 | 蓝色进度图标；不接纳新请求；所有生命周期按钮禁用 | “正在取消请求、清空队列并卸载模型。” |
| 不可用 | 不可用 | 橙色警告图标；显示后端安全失败摘要；同时提供“启动模型”和“停止模型”，由后端状态机决定能否恢复或安全卸载 | “模型当前无法安全提供推理。” |
| 未知枚举 | 无法识别的状态 | 灰色问号；禁用扩大影响的动作 | “控制台无法识别后端状态，请刷新或检查服务。” |

服务状态单独呈现，不与模型状态合并：`starting` 显示“服务启动中”，`ready` 显示“服务就绪”，`degraded` 显示“服务降级”，`stopping` 显示“服务停止中”。`service.ready` 是权威布尔值；`reason_code` 非空时显示安全代码。服务 `ready` 不替代模型 `ready`，两者都不得由前端推断。

### 5.2 启动

点击“启动模型”后只进入本地提交中状态，按钮文案为“正在提交…”。不得乐观显示“启动中”。收到权威响应后更新模型状态；若响应只确认操作已受理，显示“操作已受理”，继续依据 SSE/快照呈现。启动失败使用区域内 `InlineNotification`，展示安全错误和后端给出的下一步；只有 `retryable=true` 才显示“重试”。

### 5.3 停止确认

“停止模型”打开 Carbon 危险操作 Modal：

- 标题：“停止模型？”
- 正文：“这将取消当前活跃请求、清空当前等待队列并卸载模型。受影响的请求不会自动重放。实际结果以后端执行时的状态为准。”
- 快照补充：“当前观察到：活跃请求 {0/1} 个，等待请求 {n} 个。”并注明采样时间；
- 主按钮：“停止模型”；次按钮：“返回”；
- 若数据已陈旧，Modal 首行警告“当前数据可能已过期，后端会在执行时重新校验。”；
- 提交后不自动宣告成功。只有权威结果为已卸载才播报“模型已停止并卸载”。失败时 Modal 保持或返回控制区域显示错误，焦点移到错误摘要。

### 5.4 取消等待请求确认

每行“取消请求”打开 Modal：

- 标题：“取消此等待请求？”
- 正文：“请求 {短标识} 取消后不会执行，也不能恢复。其他等待请求的相对顺序不会改变。”
- 主按钮：“取消请求”；次按钮：“返回”。

前端不先移除行。后端确认终态后再从队列移除，并以礼貌实时区域播报“请求 {短标识} 已取消”。冲突表示请求可能已晋升、完成、超时或被其他操作影响；前端展示权威错误，立即重取快照，不将其改写为成功。

## 6. 完整 UI 状态与简体中文文案

### 6.1 通用状态规则

| 状态 | 触发条件 | 表现 | 文案指导 |
|---|---|---|---|
| 加载中 | 首次读取且无缓存 | 与最终布局同形的 Skeleton；页面标题和导航立即可用 | 可见文本仅用“正在加载运行状态…”等具体对象，避免单独“加载中” |
| 空 | 成功响应且集合为空 | 保留标题、说明和下一步；不用错误颜色 | 队列：“当前没有等待请求。” 活跃：“当前没有活跃请求。” 告警：“当前无告警。” 历史：“当前没有请求记录。” |
| 错误 | 请求失败且无可用数据，或动作失败 | 页面级或区域内 InlineNotification，含安全摘要、相关代码和允许的下一步 | “无法获取队列状态。”不得写“系统正常”或猜测原因 |
| 陈旧 | 有上次成功数据，但 SSE 中断、重同步中或超过新鲜度规则 | 原数据降级显示，顶部持久警告、最后更新时间和恢复动作；不清空内容 | “数据更新已中断，以下为 {time} 的最近结果，可能已过期。” |
| 不可用 | 后端明确声明整个能力或某个字段不可用 | 使用 `Unavailable` 占位，不显示 0、不隐藏模块；资源项同时显示来源“不可用” | “DMR 模型进程推理内存暂不可用。”附后端安全 `reason_code`；无重试资格不显示重试 |
| 提交中 | 动作 HTTP 尚未返回 | 仅对应按钮 busy/disabled；其他只读区域可用 | “正在提交…”；不得提前切换权威状态 |
| 成功反馈 | 后端给出权威终态 | 区域状态更新，必要时礼貌播报；短暂 Toast 仅作补充 | “模型已就绪。”或“请求已取消。” |
| 未知 | 新枚举或缺失必需字段 | 显式未知标签、诊断代码、禁用危险动作 | “无法识别的状态。”不得回退到默认成功 |

“空”和“不可用”严格区分：“0 个等待请求”是空；队列读取失败是不可用。“0 token”是数值；没有样本是“无数据”。“没有告警”只来自成功的空集合。

### 6.2 模型过渡状态

- 启动中：“正在加载并预热模型。完成前不能接收推理请求。”
- 就绪：“模型已完成加载和预热，可以接收推理请求。”
- 停止中：“正在取消活跃请求、清空等待队列并卸载模型。”
- 已卸载：“模型未加载，新的推理请求将被拒绝且不会排队。”
- 不可用：“模型当前不可用。”其后只追加后端安全摘要，不展示原始 controller/DMR 输出。

进度未知时使用不定进度条，不显示虚构百分比或预计完成时间。状态持续时间可由权威开始时间计算为展示值，但不得据此判定超时或失败。

### 6.3 局部错误文案模板

格式为“发生了什么 + 当前影响 + 可执行的下一步”。示例：

- “无法获取最新队列状态。当前显示的是 14:32:08 的最近结果，可能已过期。正在重新连接。”
- “停止操作未完成。模型状态仍以后端当前结果为准。请查看错误详情。”
- “无法取消该请求。请求状态可能已经变化，列表已重新加载。”
- “指标暂不可用。模型控制与请求队列不受此区域显示影响。”

禁止使用“糟糕”“未知错误”“应该没问题”“操作可能已成功”等含混文案。安全错误详情只显示后端提供的 `code` 和安全 `message`。

## 7. 后端契约消费

### 7.1 唯一契约来源和路径

前端与后端开发已通过协作通道对齐。生产者发布的稳定管理端表面为：

- 读取：`GET /admin/v1/snapshot`、`GET /admin/v1/metrics`、`GET /admin/v1/requests`、`GET /admin/v1/alerts`、`GET /admin/v1/logs`、`GET /admin/v1/operations`；
- 动作：`POST /admin/v1/model/start`、`POST /admin/v1/model/stop`、`POST /admin/v1/queue/{request_id}/cancel`，请求 body 均为空；
- 事件：`GET /admin/v1/events`，SSE，只接受 `Last-Event-ID` 恢复头，不接受 query；
- 一致性：UTC 时间、`ETag: "<snapshot_version>"` 与 `If-None-Match`；未变化为 304；
- 安全错误：固定 `{message,type,code,param,request_id,retryable,retry_after_seconds}`，外层键为 `error`；只显示生产者给出的安全字段。

`snapshot_version` 是来自全局 PostgreSQL sequence 的单调递增 int64，跨 authority epoch 不复用。客户端可按整数只应用 newer 版本并忽略旧版本；允许空洞且不得要求连续。ETag、snapshot 和 event 使用同一已提交版本。

### 7.2 已同意的客户端 wire 类型

下表逐项记录 `docs/technical/backend.md` 第 9 节的生产者类型。字段名、枚举、nullable 规则和单位不得在前端重命名后变成第二份 wire 契约；前端客户端模块直接按这些形状解码，在组件边界外不得出现 `any`。

| 类型 | 生产者字段/枚举 | 消费位置 |
|---|---|---|
| AdminSnapshot | `snapshot_version, generated_at, service, model, queue, resources, active_alert_count` | 总览及动作前确认 |
| ServiceSnapshot | `state` 为 `starting`、`ready`、`degraded`、`stopping` 之一；另含 `ready,authority_epoch` 和 nullable `reason_code` | 服务状态带 |
| ModelSnapshot | `state` 为 `unloaded`、`starting`、`ready`、`stopping`、`unavailable` 之一；另含 `transition_started_at`、nullable `operation_id`、nullable `failure:{code,message,retryable}` | 生命周期与安全失败 |
| ActiveRequest | `id,status:"active",endpoint,stream,reasoning_enabled,enqueued_at,started_at` 或 `null` | 唯一活跃请求 |
| WaitingRequest | `id,status:"waiting",endpoint,stream,reasoning_enabled,position,enqueued_at,deadline_at,can_cancel` | FIFO 表 |
| ResourceSnapshot | `status` 为 `available`、`partial`、`unavailable`、`stale` 之一；`cpu_percent,cpu_source`；`unified_memory_used_bytes,unified_memory_total_bytes,unified_memory_source`；`disk_used_bytes,disk_total_bytes,disk_source`；`metal,metal_source`；另含 `sampled_at,reason_code`。source 全集为 `api_container`、`dmr_process`、`project_storage`、`unavailable`；Metal 为 `enabled`、`disabled`、`unknown` | 资源摘要 |
| RequestPage | `items,next_cursor`；item 为生产者列出的请求元数据，`status` 为 `waiting`、`active`、`succeeded`、`failed`、`cancelled`、`queue_timeout`、`interrupted`、`rejected` 之一；nullable 时间、计数、code 保持 null | 请求历史 |
| MetricsResponse | `from,to,granularity,series[]`；series 包含 `bucket_start,request_count,outcomes` 全状态计数、三类 token、nullable throughput/TTFT/duration 平均值 | 指标图表和同源表格 |
| AlertPage | `items,next_cursor`；item 含 `id,severity,code,message,first_seen_at,last_seen_at,state,occurrences`；severity 为 `info`、`warning`、`critical`，state 为 `active`、`resolved` | 告警 |
| LogPage | `items,next_cursor`；item 含 `id,occurred_at,level,event_code,request_id,operation_id,message`，level 为 `info`、`warning`、`error`，无任意 context map | 日志 |
| OperationsResponse | `retention,backup,restore_proof,model_operations`；运维 outcome 为 `succeeded`、`failed`、`unknown`；模型 operation 为 `start`、`stop`、`reconcile_unload`，状态为 `running`、`succeeded`、`failed`、`indeterminate`、`interrupted`，observed state 为 `loaded`、`unloaded`、`unknown` | 数据页、操作结果 |
| ModelActionAccepted | 202 `{operation_id,status:"running",accepted_at}` | 启动/停止受理，不代表完成 |
| CancelResult | 200 `{request_id,status:"cancelled",cancelled_at,snapshot_version}` | 取消权威终态 |
| AdminEvent | `{event_id,snapshot_version,occurred_at,type,data}`；type 为 `snapshot_changed`、`model_changed`、`queue_changed`、`metrics_updated`、`alert_changed`、`operation_changed`、`resync_required` | 查询失效与恢复 |

`GET /admin/v1/requests` 只接受 `cursor` 与 `limit=1..100`，默认 50；`GET /admin/v1/alerts` 同为不透明 cursor；`GET /admin/v1/logs` 额外只接受 `level=info|warning|error`。前端不增加未发布的状态、时间、排序或告警筛选。`GET /admin/v1/metrics` 只使用四个合法组合。`artifact_name` 只按 basename 展示。所有 nullable 值保留“不适用/未知”，不得转换为 0、空串或成功。

### 7.3 SSE、轮询与恢复

1. 首屏先读取快照和当前路由所需资源，再建立 SSE；页面无需等待事件连接即可展示权威 HTTP 结果。
2. 保存最近已应用的十进制 `event_id` 于内存；浏览器重启后不持久化游标，无 `Last-Event-ID` 时按服务器首个 `snapshot_changed` 立即读取快照。
3. 正常事件只使 `data.changed` 指向的查询失效并重取。事件 data 不是资源完整事实，不做部分字段合并。
4. 服务端每 15 秒发送 comment heartbeat。断线使用 SSE 重连并发送 `Last-Event-ID`；断线本身不代表动作成功或模型故障。
5. 服务器最多补发 1000 条；收到 `resync_required` 时立即重取 snapshot 和当前路由相关 GET，成功后再移除陈旧提示。
6. 对重复或已处理的 `event_id` 幂等忽略；未知事件类型或无法解析的 envelope 进入显式兼容性错误并全量重同步。只应用 snapshot/event 中大于当前已应用值的 `snapshot_version`；版本空洞合法，不触发错误。
7. 页面可见时每 2 秒条件读取 snapshot，历史、指标和 operations 每 30 秒刷新，均使用 `If-None-Match`；304 不触发视觉刷新。SSE 正常时轮询仍是生产者规定的兜底，而非第二状态源。
8. 页面隐藏时暂停 30 秒读取；恢复可见时立即刷新 snapshot 和当前路由数据。组件卸载时中止 HTTP 并关闭其不再使用的订阅。
9. 资源陈旧完全采用 `resources.status=stale`，生产者在样本超过 15 秒时设置并保留最后样本及 provenance。`partial` 保留可用项并逐项把不可用数值显示为“无法获取”；`unavailable` 不显示 0。前端不得用自己的时钟或其他来源改写这些状态。
10. 全局数据陈旧是展示状态：SSE 断开且最近一次 2 秒 snapshot 兜底也失败时，保留最后结果并显示最后 `generated_at`；任一新快照成功后解除。它不是业务状态。

### 7.4 动作一致性

- 动作请求不得自动重试；用户可重试仅限后端 `retryable=true`，并遵守 `retry_after_seconds`；
- 双击通过 pending 状态抑制，但后端仍负责并发、幂等、冲突和最终状态；
- 动作 HTTP 成功只表示契约规定的受理或结果，不允许客户端统一解释为完成；
- 动作响应后立即条件重取快照；后续 SSE 重复通知必须幂等；
- `409` 或其他生产者定义的冲突先显示安全结果，再重取权威快照；
- `503` 不被前端改写为离线或已卸载；只显示后端错误语义；
- 取消路径中的 `{id}` 必须由 Requests/Snapshot 返回，不接受用户自由输入。

## 8. 可访问性

目标为 WCAG 2.2 AA，并以真实键盘、屏幕阅读器和缩放场景验证。

### 8.1 键盘与焦点

- 所有功能只用键盘可完成；DOM 顺序与视觉顺序一致；不使用正 tabindex；
- 首个元素为跳转链接，随后为 Header、导航、主内容；当前导航项使用 `aria-current="page"`；
- 焦点环至少 2px，和相邻颜色达到 3:1；任何状态均不移除 `:focus-visible`；
- Modal 打开时焦点进入标题或安全的“返回”按钮，焦点困在 Modal；Esc 等同“返回”，提交中不得用 Esc 遗失结果；关闭后焦点回到触发按钮，若该行消失则回到队列表标题；
- 表格行操作使用带请求短标识的 accessible name，如“取消请求 abc123”；
- Tooltip 不承载唯一信息，鼠标悬停和键盘焦点均可触达，Esc 可关闭；
- 目标尺寸至少 24×24 CSS px，主要和危险按钮至少 40px 高；200% 缩放时不丢功能，400% 下按窄屏布局工作。

### 8.2 实时区域

- 页面放置一个视觉隐藏的 `aria-live="polite"`、`aria-atomic="true"` 区域，只播报语义变化：模型生命周期变化、动作权威终态、队列取消结果、连接转为陈旧或恢复；
- 不播报每次轮询、计时器秒数、资源样本或队列等待时长更新；
- 动作失败和模型变为不可用使用 `role="alert"`，但同一错误只播报一次；
- 加载容器使用 `aria-busy`；加载完成后播报区域名称而不是整页内容；
- 状态标签包含可读文本，不能只读颜色或图标名称。

### 8.3 表格与图表

- DataTable 使用原生表格语义、`caption`、列头 `scope`；队列表 caption 明确“按 FIFO 顺序，不能重排”；
- 所有管理表均按生产者固定顺序展示，不提供排序按钮；列头保持普通 `scope` 语义，不使用 `aria-sort`；
- 窄屏不把表格改成失去表头关联的无语义卡片。使用横向滚动容器，首列和行操作保持可发现；容器获得描述文本“表格可横向滚动”；
- 每个图表有可见标题、单位、时间范围、文字摘要及同数据表格；图例可键盘操作并有文本标签；
- 序列同时用颜色、线型和点形区分。缺失样本用断线，不用背景色填补；
- Tooltip 内容可由键盘点访问，且不要求精细指针；若 Carbon Charts 无法满足某项键盘行为，默认展示表格而不是交付不可访问图表。

### 8.4 动效与认知负担

遵守 `prefers-reduced-motion: reduce`：关闭旋转、脉冲、图表补间和页面过渡，只保留即时状态切换。不使用自动滚动、闪烁或倒计时动画。常规模式下只允许 120 至 180ms 的颜色/展开过渡；生命周期进度动效不携带虚构进度。

所有破坏性操作使用具体动词，不用“确定吗”。时间同时提供绝对值，避免只写“刚刚”。错误不自动消失；成功 Toast 最少保留 5 秒且状态本身仍在页面可见。

## 9. 视觉系统

### 9.1 主题与色彩

MVP 使用单一浅色主题，减少未验证的双主题组合。遵循 Carbon Gray 10 背景、White 内容层、Gray 100 主文字、Blue 60 唯一交互强调色。语义颜色只用于状态：Green 50 就绪/成功、Red 60 破坏性/失败、Orange 40 警告/陈旧、Gray 60 已卸载/未知。每种颜色必须配图标、文本和形状：

- 就绪：勾选 + 实心标签；
- 过渡：进度图标 + 描边标签；
- 已卸载：减号 + 中性标签；
- 不可用/警告：警告三角 + 描边标签；
- 失败/破坏：错误图标 + 高对比文本。

正文和背景至少 4.5:1，大号文本至少 3:1，非文本 UI 与焦点至少 3:1。不得使用红绿作为唯一差异。

### 9.2 字体、间距与形状

- 字体：`IBM Plex Sans, PingFang SC, Microsoft YaHei, system-ui, sans-serif`；标识/数值可用 `IBM Plex Mono` 并回退系统等宽字体；
- 正文 14px/20px，辅助 12px/16px，页面标题 28px/36px；核心状态不低于 14px；
- 使用 Carbon 2x Grid，页面最大宽度 1600px；高密度表格行高不低于 40px；
- Carbon 的方正工业风为准：容器 0 至 2px 圆角，按钮和标签不做胶囊化，禁止漂浮大圆角卡片和装饰阴影；
- 分组优先使用网格、留白、分隔线和层级背景，仅在真正独立的状态单元使用 Tile。

### 9.3 响应式

- `>= 1280px`：16 列，SideNav 展开；总览模型控制占 6 列，当前执行/队列占 10 列；资源四项同排；
- `768–1279px`：8 列，SideNav 可折叠；主要区域纵向排列，资源 2×2；
- `< 768px`：4 列，Header 菜单；所有主区域单列；动作按钮占可用宽度；表格横向滚动；Modal 近全屏但保留安全边距；
- 最小支持宽度 320px，不允许页面整体横向滚动；仅数据表和图表局部可横向滚动；
- `100dvh` 只用于窄屏导航/Modal 的最大高度，不用固定视口高度裁切主内容；支持安全区域 inset。

## 10. 浏览器支持与性能

支持验收时稳定版本及其前一个主要版本的 Chrome、Edge、Firefox、Safari；MVP Apple Silicon Mac 上 Safari + VoiceOver 与 Chrome 为必验组合，Firefox/Edge 做功能与布局兼容检查。明确不支持 Internet Explorer。SSE、`AbortController`、CSS Grid、`prefers-reduced-motion` 和 `dvh` 不满足时不得靠静默 polyfill 改写业务行为；布局对 `dvh` 提供普通 block 流回退。

性能预算：

- 路由级代码拆分，图表库仅在 `/metrics` 加载；
- 首屏不加载历史全量或日志全量，所有列表服务端分页；
- SSE 事件批量使查询失效，避免每个资源样本触发整页渲染；
- 趋势点数遵循生产者粒度，客户端不持有无限序列；
- Skeleton 预留最终区域尺寸，避免状态刷新产生布局位移；
- 断开/卸载时中止在途读取并清理事件连接和计时器。

## 11. 安全与内容最小化

- 所有后端文本按纯文本渲染，不使用 `dangerouslySetInnerHTML`；
- URL 查询参数只包含生产者允许的指标时间窗/粒度、日志级别和不透明分页游标，不包含请求正文或密钥；
- 不接收、记录或上报 prompt、response、reasoning、tool arguments；
- 浏览器日志不打印完整响应、事件、错误对象或请求标识集合；
- 不在 localStorage、IndexedDB、Service Worker cache 中持久化管理数据。仅内存缓存，刷新即失效；
- 不使用 Service Worker 离线展示，以免把旧运维事实误认为当前状态；
- 控制台无登录是批准的产品事实，但所有副作用仍由后端验证；
- 禁止在 UI 暴露 controller/DMR 地址、数据库信息、备份绝对路径或任意命令入口。

## 12. 交付与兼容性

前端实施依赖顺序：

1. `docs/technical/backend.md` 中的管理端 schema 成为唯一可生成来源；
2. 固定 Carbon 依赖并建立 tokens、Shell、错误边界和查询基础设施；
3. 先实现快照、模型动作和请求队列，再实现指标、告警/日志、数据/备份；
4. 接入 SSE 恢复和条件轮询；
5. 完成真实浏览器、键盘、屏幕阅读器、缩放和断线恢复验证。

后端契约变化必须通过生产者 schema 兼容迁移。前端不得用别名、默认成功分支或宽松 `any` 掩盖不兼容枚举。静态前端回滚只回滚展示版本；因为后端是权威，回滚版本必须仍兼容当前生产者 schema，否则整套版本一并回滚。

## 14. 浏览器验证场景

所有场景必须在真实 Compose/DMR 环境、真实浏览器执行，保存浏览器截图/录屏、网络请求和对应后端证据；不得用静态 mock 宣称通过。

1. **首次访问与语言：** 清除浏览器站点数据，直接访问每个路由；确认无登录、所有产品文本为简体中文、深链刷新成功、跳转链接和标题层级正确。覆盖 AC-023。
2. **冷启动：** 平台冷启动后打开总览；确认显示“已卸载”，无活跃和等待项，启动可用；API 503 与队列未增长由联合证据关联。覆盖 AC-002。
3. **启动成功与失败：** 分别触发真实成功和受控失败；确认提交中不乐观切状态，按已卸载→启动中→就绪变化；失败进入不可用且不曾显示就绪。覆盖 AC-003、AC-024。
4. **停止破坏性流程：** 在一个活跃加若干等待请求时打开确认 Modal；核对数量/采样时间、键盘焦点和文案，执行停止；观察停止中，最终已卸载，队列清空，各请求非成功。覆盖 AC-004、AC-024。
5. **FIFO 与取消：** 建立一个活跃加 20 个等待请求；核对顺位和深度，键盘取消中间项；其余相对顺序不变且页面无排序/拖拽。覆盖 AC-016、AC-017、AC-020。
6. **超时与重启：** 观察真实 `queue_timeout` 和重启后的 `interrupted`；标签、详情和实时播报均可区分，且无重放入口。覆盖 AC-019、AC-021、AC-022。
7. **指标一致性：** 执行一次条件记录清楚的真实请求；比较页面请求数、三类 token、吞吐、TTFT、时长和后端证据；切换图表/表格并验证缺样本不是 0。覆盖 AC-026、AC-028。
8. **资源来源与降级：** 核对四项固定中文标签、source 和后端证据；分别使一项不可用，确认 `partial` 保留其余项目、不可用项显示“无法获取”而非 0；全部不可用时显示 unavailable；陈旧时保留样本与原 provenance。确认页面没有“整机 / 物理主机 / Docker VM CPU、内存或磁盘”表述，也没有虚构 GPU 利用率或把 CUDA 表述为 Metal。覆盖 AC-025。
9. **告警边界：** 触发受控告警；确认告警和安全结构化日志可见，无浏览器通知、邮件、IM 或 webhook 入口。覆盖 AC-027。
10. **数据与备份：** 使用受控时间、备份和恢复证据检查 30 天、每日/7 天和恢复结果；搜索 DOM、网络响应及浏览器存储，确认无正文。覆盖 AC-029 至 AC-033。
11. **SSE 恢复：** 断开 SSE 后改变后端状态，再恢复；确认出现陈旧警告、保留最后更新时间、通过 `Last-Event-ID` 恢复或 `resync_required` 全量同步，最终状态与快照一致，未把断线显示为模型故障。
12. **乱序与未知值：** 注入测试环境允许的重复/过期事件和未知枚举；确认不回退版本、不显示成功，进入显式未知并全量重同步。
13. **键盘与屏幕阅读器：** 不使用鼠标完成导航、启动、停止确认、取消、日志级别选择、游标分页和图表数据表切换；验证焦点返回、Modal 陷阱、状态播报不重复。
14. **视觉可访问性：** 在 Safari 与 Chrome 验证 320px、768px、1280px，200%/400% 缩放、系统减少动态效果、高对比检查和文本/状态非仅颜色表达。
15. **内容最小化：** 检查 DOM、console、localStorage、IndexedDB、Cache Storage、URL、SSE 和前端错误输出；不得出现提示词、回答、推理内容或工具参数正文。

## 15. 失败与恢复决策表

| 故障 | 页面行为 | 恢复条件 |
|---|---|---|
| 首次快照失败 | 页面级错误，保留导航；不显示默认模型状态 | 成功取得权威快照 |
| SSE 断开 | 保留最近数据；snapshot 兜底也失败后标陈旧 | `Last-Event-ID` 续传成功，或 `resync_required` 后全量重同步成功 |
| 资源指标部分不可用/全部不可用/陈旧 | 按 `resources.status` 和逐项 source 显示可用值、无法获取或最后样本；不影响模型/队列 | 新 Snapshot 给出生产者权威状态；前端不自行改写 |
| 历史/日志失败 | 对应表局部错误，当前游标或日志级别保留 | 同查询成功 |
| 动作网络结果不明 | 明确写“结果待确认”，禁用重复提交并重取操作/快照 | 后端 Operations 或快照给出权威结果；不得猜测 |
| 操作冲突 | 显示安全冲突，立即刷新相关资源 | 新快照成功 |
| 未知事件/枚举 | 忽略其业务解释、标未知、全量同步 | 兼容快照或前端升级 |
| `api` 整体不可用 | 所有最后数据标陈旧；无缓存则不可用；不提供离线动作 | `api` 成功返回 |
